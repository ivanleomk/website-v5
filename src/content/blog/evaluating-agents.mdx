The hardest problem now is finding the right problem for models to solve.

It's August 2026. I spent late 2025 building [Manus](https://manus.im). Before that I wrote [Building Reliable LLM Applications](/blog/building-reliable-llm-applications). That post still holds. This is a quick thought about how the instrument changed.

Broadly speaking, agents still work like functions. We throw in some input, we get an output, and we compare it against a ground truth or a rubric. That loop didn't change. Evaluating a model (question in, letter out) is still not evaluating an agent (trajectory, tools, environment state). The scope of what we throw at the function did.

I said this at an [Artificial Analysis talk](http://luma.com/qdl9mr2e?tk=P3UvLA) earlier this year. Most models crush easy benchmarks over time as we scale data and parameter count. They don't need to specialise in the test. They train on more data, larger corpora, and other axes like test-time compute, and the quiz dies. Benchmarks have shorter life cycles than they used to.

Even defining a pass has gotten messier. The rubric is harder. Detecting cheating is now part of the job: [Z.ai](https://huggingface.co/blog/zai-org/glm-52-blog) had to run a rule filter plus an LLM judge on tool calls during RL because the agent would `curl` the answer. You also have to stop the model from going to look up the key. In July 2026 an eval agent [broke into Hugging Face](https://huggingface.co/blog/agent-intrusion-technical-timeline) trying to steal test solutions rather than solve the task. And we probably don't know the capability ceiling on a given task, because [it's too expensive to measure](https://x.com/polynoamial/status/2064210146558136827), as Noam Brown put it.

That's a long way from GPT-2, when the eval was [LAMBADA](https://aclanthology.org/P16-1144/): finish the last word of a sentence and sound convincing.

Rubrics also have become incredibly complicated, with [Cognition's new FrontierCode benchmark](https://cognition.com/frontiercode) being a great example of this.

They had to hire 20+ world-class developers to build realistic, diverse and challenging tasks, spending more than 40 hours per tasks to define a shared rubric over many rounds of reviews. And even when a benchmark still works, a pass is no longer just "did the tests go green." **You also have to catch cheating**.

[Z.ai](https://huggingface.co/blog/zai-org/glm-52-blog) had to run a rule filter plus an LLM judge on tool calls during RL, because the agent would just download the answer. In July 2026, an eval agent [broke into Hugging Face](https://huggingface.co/blog/agent-intrusion-technical-timeline) trying to steal the solutions instead of solving the task. In the post-mortem, the wild part was the agents talking to each other: they [turned a shared Artifactory into a message board, then kept going via directory names](https://www.youtube.com/watch?v=87DyyMV0kCY) after the first channel got shut down.

We also saw this for publicly cited benchmarks like SWE-Bench Pro with Cursor finding that [63% of successful Opus 4.8 Max resolutions retrieved the fix rather than derived it](https://cursor.com/blog/reward-hacking-coding-benchmarks).

Compare that to [evals in 2025](/blog/building-reliable-llm-applications), when we were still in RAG-land and a model that stayed coherent across a few tool calls between user turns felt like a lot.

The hard problem has shifted to finding the right problem. We used to struggle to get a model to pick the right letter on a quiz. Now the models crush those quizzes, and with the wrong sandbox they might walk out with the answer key.

[Shunyu Yao](https://ysymyth.github.io/The-Second-Half/) called this AI's halftime.

1. **First Half**: invent better training methods.
2. **Second half**: define the right problem.

I could get behind that. But let's take a quick walk down memory lane to see just how fast things have changed.

## Starting with Pre-Training

Training used to be next-word prediction. In 2019, [OpenAI trained GPT-2](https://openai.com/index/better-language-models/) based off predicting the next word in 40GB of internet text.

This seems almost trivial for the models today.

By the time we had reached GPT-3 in 2020, we had a training budget of 300 billion tokens and a model that scored 86.4% on LAMBADA. **This was no longer the right evaluation to hill climb on**.

The next test that still had headroom was [GSM8K](https://arxiv.org/pdf/2110.14168) where models were tasked to solve grade school math problems.

In 2022, Jason Wei showed that using few-shot examples in the prompt with chain-of-thought could boost performance significantly, taking PaLM 540B from 17.9% to 56.9%.

I found something similar when [benchmarking structured outputs on GSM8k](https://python.useinstructor.com/blog/2024/09/26/bad-schemas-could-break-your-llm-structured-outputs/) in 2024, showing that adding a `reasoning` field in the response object increased model accuracy by 60% on the GSM8k dataset.

When these quizzes started saturating, The [Google-Proof Q&A Benchmark](https://arxiv.org/abs/2311.12022), more commonly known as GPQA, became a candidate for an unsaturated evaluation that we could hill-climb on. At the time, the strongest GPT-4-based baseline was only 39%.

## Scaling Up

If a scratchpad in the prompt moves GSM8k, why not just bake it in?

It started with OpenAI announcing that they trained a new series to spend more time thinking before it responds. And as a result, we get [o1-preview](https://openai.com/index/introducing-openai-o1-preview/) that drops on 12 September 2024.

On GPQA Diamond, GPT-4o was 50.6% pass@1. o1-preview was 73.3%, past the PhD line OpenAI recruited for that eval. Same loop. New method. The test still had room, so the jump printed.

Then just a few months later, we see [Deepseek-R1](https://arxiv.org/abs/2501.12948) on 20 January 2025 which matched the performance of O1 with open weights and pure GRPO at scale. GRPO had been introduced earlier by [DeepSeek Math](https://arxiv.org/pdf/2402.03300) which had used it to match GPT-4 on the MATH eval.

R1 provided open weights and a code-baed reward which allowed it to drive scores on evals like AIME from 15.6% to 71%.

So we were seeing that with the right eval to hill climb on, we developed models which were able to expend more compute at test time to get better results. Test-time scaling had been developed.

## Agents

At the same time we were measuring knowledge and reasoning, we were also seeing evals that measured the ability of models to work autonomously. This led to the creation of [SWE-Bench](https://www.swebench.com/) in 2023.

At launch, Claude 2 resolved [1.96% of issues](https://arxiv.org/abs/2310.06770) with BM25 retrieval, and 4.8% if you handed it the right files. That is the "model in a repo" number. Bare completion, no agent loop. **Note that this was a single turn and the model had to output a patch**.

A real item from the benchmark is `django__django-10097` ([SWE-bench](https://github.com/princeton-nlp/SWE-bench), [PR](https://github.com/django/django/pull/10097)). You are not guessing a word. You are finding the right file in Django, writing a fix, and surviving two test sets: **fail-to-pass** (the bug is gone) and **pass-to-pass** (nothing else broke).

In March 2024, [Cognition announced Devin](https://x.com/cognition/status/1767548763134964000?lang=en), demonstrating an autonomous loop that scored 13.86% on SWE-bench. Just weeks later in April 2024, [the Princeton team released SWE-agent](https://arxiv.org/pdf/2405.15793), showing how an Agent-Computer Interface (ACI) harness could take the open-source baseline from 1.31% to 12.47% with GPT-4o by letting models iteratively browse, edit, and run repo tests

By March 25 2025, [Gemini 2.5 Pro](https://blog.google/innovation-and-ai/models-and-research/google-deepmind/gemini-model-thinking-updates-march-2025/) had launched with a score of 63.8% on SWE-Bench Verified. The benchmark was slowly being saturated with [OpenAI pronouncing it dead in February 2026](https://openai.com/index/why-we-no-longer-evaluate-swe-bench-verified/).

## Multi-Turn Evals

SWE-Bench still hands the agent the whole ticket up front. The next step was a user who talks back.

[τ-bench](https://arxiv.org/abs/2406.12045) is a great example of an evaluation which uses another Language Model posing as a user with a goal in mind.

The agent being evaluated then needs to interact and resolve the user's query, before being graded on the final result based on a given rubric.

Here's an example from the paper of a sample user that the agent was tasked to interact with.

> You are mia_li_3668. You want to fly from New York to Seattle on May 20 (one way). You do not want to fly before 11am est. You want to fly in economy. You prefer direct flights but one stopover also fine. If there are multiple options, you prefer the one with the lowest price. You have 3 baggages. You do not want insurance. You want to use your two certificates to pay. If only one certificate can be used, you prefer using the larger one, and pay the rest with your 7447 card.

Even today, on their standard Banking leaderboard, Claude Opus 5 scores a measly 48.7%. Another one that I liked was [TERMS-Bench](https://terms-bench.github.io/) which aims to get a model to act as a negotiator.

It uses a determinstic script to simulate a counterpart as seen in the pseudocode below.

```python
import random

def seller_move(bid, ask, r, kappa, rng):
    if bid >= r and rng.random() < kappa:
        return "accept", bid

    ask = ask - rng.uniform(0.15, 0.35) * (ask - r)
    return "offer", max(ask, r)

rng = random.Random(7)
ask, r, kappa = 78.78, 59.48, 0.56

for bid in [50.0, 55.0, 58.0, 61.0]:
    action, ask = seller_move(bid, ask, r, kappa, rng)
    print(action, round(ask, 2))
    # "I can come down to {ask}." — a template, not a model
```

This lets us put a model on one side of a negotiation without putting another model on the other. Below, Gemma 4 31B is the buyer. The scripted seller will not go below $59.48$. Gemma will not pay above $99.13$. That interval is the ZOPA.

Gemma accepts at $60.21$ — just above the seller's floor — and keeps almost the entire gap. That is a good deal for the buyer, not a missed exploration of the zone.

## Conclusion

If anything there's a clear pattern for these breakthroughs. We get a new eval, we find a method that climbs it.

LAMBADA resulting in us scaling up pre-training. Evals like GPQA and GSM8k eventually resulted in techniques like Chain of Thoughts and test-time compute showing up. SWE-bench motivated the invention of the harness

Models today already know the capital of France. The question is whether the model can do the work on a simulated set of tasks that you actually care about.

An evaluation is how you decide what good means for you, and which model is best for that. Vibes will get you a demo. They will not let you iterate when the weights change next week.

You don't need to invent the next SWE Bench today, just start by writing some [stupid evals](/blog/write-stupid-evals) and progressively making things more complicated.

We've now reached the point where models require domain experts to determine if they've done a good job. That's why companies like Harvey published [BigLaw Bench](https://www.harvey.ai/blog/introducing-biglaw-bench).
